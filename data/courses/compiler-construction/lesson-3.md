# Lesson 3: Syntax Analysis

## The Role of the Parser
Once the Lexer has converted the source code into a stream of tokens, the **Syntax Analyzer** (or Parser) takes over. Its job is to determine whether that stream of tokens follows the grammatical rules of the programming language.

If the token stream is valid, the parser constructs a **Syntax Tree** (specifically, an Abstract Syntax Tree or AST). The AST is a hierarchical, tree-like data structure that perfectly represents the structural logic of the code.

## Context-Free Grammars (CFG)
While Regular Expressions are powerful enough to identify simple tokens, they are mathematically incapable of defining nested structures (like matching parentheses or nested `if` statements). 

To define syntax, compilers use **Context-Free Grammars (CFGs)**. A CFG consists of:
- **Terminals**: The tokens produced by the lexer (e.g., `if`, `(`, `IDENTIFIER`).
- **Non-terminals**: Syntactic variables that represent larger structures (e.g., `Statement`, `Expression`).
- **Production Rules**: Rules defining how non-terminals can be expanded into terminals and other non-terminals.

## Parsing Strategies
There are two main approaches to parsing:
1. **Top-Down Parsing**: Builds the syntax tree from the root down to the leaves. Examples include *Recursive Descent Parsers* and *LL Parsers*. These are generally easier to write by hand.
2. **Bottom-Up Parsing**: Builds the tree from the leaves up to the root. Examples include *LR Parsers* (like SLR, LALR). These are more powerful and are typically generated by tools like `Yacc` or `Bison`.
